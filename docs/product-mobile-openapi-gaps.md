## Пробелы контракта

| Элемент макета | Текущий контракт | Что нужно согласовать с API | Текущее отображение |
| --- | --- | --- | --- |
| Цветовые кружки и название выбранного цвета | `ProductVariantGroup` содержит только `id`, `label`, `options`; `ProductVariantOption` не содержит значение цвета | Явный тип группы (например, `displayType: text / color`) и цвет образца (`swatchColor` в HEX либо URL образца) у опции. Название цвета уже есть в `label` | Текстовые кнопки вариантов. Цвет не вычисляется из локализованного названия или ID |
| Значки доставки и самовывоза возле магазина | В `ProductOffer` и `ProductOfferMerchant` нет признаков доставки, самовывоза или адресов | Доступность доставки/самовывоза для предложения, при необходимости сроки, стоимость, адреса и зависимость от выбранного города. Неизвестное значение должно отличаться от отсутствующей услуги | Значки не отображаются, чтобы не утверждать наличие услуги без данных |
| Отдельный блок Similar Products | Нет связи рекомендаций с текущим продуктом; `/products` возвращает общий список | Endpoint похожих товаров с ID/slug исходного продукта либо явно определённое поле списка в ответе продукта | Существующий блок More Products использует общий список; он не выдаётся за подборку похожих товаров |

## Данные, которые уже предусмотрены

`imageUrls`, `categoryBreadcrumbs`, `variants`, `summary`, `attributes.groups`,
`description`, цены и ссылки предложений достаточны для галереи, вкладок,
характеристик и закреплённой панели лучшей цены. Лучшая цена и число предложений
вычисляются из `offers`.

Пустые `description`, `merchant.logoUrl` и `merchant.phone` в фактическом ответе
API — вопрос наполнения данных: поля уже есть в контракте. Соответствующие
необязательные элементы не заполняются вымышленными значениями.

OpenAPI и generated-файлы в рамках мобильной адаптации не изменялись.
